# 0002 — Reusable workflows belong to CAD Workbench

Status: accepted ownership direction; extraction candidate pending independent acceptance.

The user replaced the draft three-repository workflow-library proposal with CAD Workbench ownership of reusable capabilities, workflows and skills. Project repositories retain authoritative source and project-local generation logic, requirements, assets, decisions, acceptance records and release history. Workbench owns the reusable policies, templates, two skills, catalog, contracts and preserved legacy viewer source.

Capabilities describe an ability; workflows order bounded uses and gates; skills guide an agent; runtime providers execute; project instances bind concrete source and evidence. A catalog entry does not establish implementation or acceptance. The twelve categories and two recipes are discovery documents, not a workflow engine. Uninspected capabilities stay reported/unknown.

Small explicit external bindings pin Workbench policy manifests separately from project revisions and commands. No shared runtime is forced. CAD, artifact/slicer and physical evidence remain separate. Source plus parameters remains geometry authority.

The untracked workflow-library draft is an input, not an accepted authority. Its separate repository and remote are retained recoverably by the coordinator; its ownership statements are superseded. Copying the draft wholesale or leaving duplicated live policies in design-projects would create competing authorities and is rejected. Project compatibility pointers may link the pinned Workbench counterparts.

The extraction mapping preserves old paths and SHA-256 identities. Legacy viewer source is unchanged and its existing service/runtime dependencies remain explicit; no installation or service operation is part of this decision. Existing upstream cadgen remains pinned, with small adapters preferred over replacement.
